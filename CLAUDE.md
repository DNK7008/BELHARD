# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

Учебные работы по курсу BELHARD. Каждый урок или домашнее задание живёт в своей папке (`homework-1`, `lesson-2`, ...) и ни от чего больше не зависит — общего кода между папками нет и заводить его не нужно.

Автор учится, а не поставляет продакшен. Объясняй решения, а не только вноси правки; предпочитай простой понятный код умному.

Весь контент и комментарии — на русском.

## Сборка и запуск

Сборки нет. Ни `package.json`, ни зависимостей, ни тестов, ни линтера — команд для запуска не существует.

Результат проверяется открытием HTML-файла в браузере:

```
start homework-1\index.html
start game-8-bit\cat\index.html
start homework-4\index.html
start homework-4\diagnostic\index.html
start homework-4\code-check\index.html
start homework-4\simulation\index.html
```

Локальный сервер нужен, если проверяешь Open Graph или JSON-LD внешними валидаторами (им требуется настоящий URL) — по `file://` разметка страницы работает полностью.

Второй случай, когда без сервера не обойтись, — проверка через Playwright MCP: он не открывает `file://` («Access to "file:" protocol is blocked»). Для него раздай корень репозитория локальным сервером — этот вариант отдаёт файлы с `Cache-Control: no-store`, чтобы браузер после правки не показывал старый CSS. Страницы тогда открываются по `http://127.0.0.1:8765/<папка>/`. Запускай команду из корня репозитория и в фоне: сервер работает, пока его не остановишь.

```
python -c "import http.server as s, functools as f; H = type('H', (s.SimpleHTTPRequestHandler,), {'end_headers': lambda self: (self.send_header('Cache-Control', 'no-store'), s.SimpleHTTPRequestHandler.end_headers(self))}); s.ThreadingHTTPServer(('127.0.0.1', 8765), f.partial(H, directory='.')).serve_forever()"
```

Корневой `index.html` — оглавление для GitHub Pages (`https://dnk7008.github.io/BELHARD/`). Появилась новая работа со страницей — добавь на неё ссылку туда.

## homework-1 — резюме-одностраничник

Весь сайт — один `index.html` (~46 КБ): разметка, стили и скрипты в одном файле, картинки в `assets/image/`. Это осознанное требование задания, а не временное решение — не разноси файл на части и не добавляй сборщик.

Ключевые вещи, которые не видны из беглого чтения:

**Тема Tailwind объявлена инлайн.** Tailwind подключён через play-CDN, а кастомные цвета (`ink-900`, `accent`, `accent-soft`) и шрифты заданы в блоке `tailwind.config` внутри `<head>`. Эти классы существуют только благодаря этому блоку: при переносе разметки в другой файл вёрстка развалится молча, без ошибок в консоли.

**Комментарий про `assets/styles.css` устарел.** В `<head>` написано, что «актуальная версия — собранный styles.css». Такого файла в репозитории нет и собирать его не планируется.

**Тёмная тема — на классе, а не на media-запросе.** Класс `dark` висит на `<html>`, переключается кнопкой `#themeToggle` и запоминается в `localStorage`; по умолчанию тёмная. Поэтому любой новый цвет пишется парой: светлый и `dark:`-вариант, иначе элемент пропадёт в одной из тем.

**Печать — полноценный второй режим отображения.** Блок `@media print` превращает страницу в компактное резюме для Ctrl+P (кнопка «Скачать PDF» просто зовёт `window.print()`). Каждый новый интерактивный элемент — кнопку, форму, навигацию — помечай классом `no-print`, иначе он окажется в PDF. Обработчик `beforeprint` принудительно раскрывает анимированные блоки, чтобы они не ушли в печать невидимыми.

**Анимации AOS отключаются при `prefers-reduced-motion`.** Проверка сделана и в CSS, и в JS при инициализации — если добавляешь новую анимацию, поддержи оба пути.

**Контакты продублированы в трёх местах:** видимый список в секции «Контакты», иконки в подвале и блок JSON-LD (`schema.org/Person`) в самом низу файла, плюс `og:`-теги в `<head>`. Меняешь контакт — правь везде, иначе поисковики и превью ссылок будут показывать старое.

**Данные в резюме — заглушки.** Контакты, ссылки на проекты, адрес сайта и ID формы Formspree выдуманы и ждут реальных значений. Не выдавай их за настоящие и не рассылай страницу в таком виде.

## game-8-bit/cat — 8-битная игра «Дорога домой»

Ретро-платформер к бонус-челленджу занятия 2: кошка Лапка выбралась из коробки в лесу и бежит домой, где её ждёт девочка Соня. Три уровня (утро, день, закат), управление с клавиатуры и с сенсорного экрана. Живая ссылка: `https://dnk7008.github.io/BELHARD/game-8-bit/cat/`.

Вся игра — один `index.html` без внешних файлов, библиотек и шрифтов: графика нарисована в коде, музыка синтезируется Web Audio. Это требование задания (двойной клик — и играешь, работает офлайн и на GitHub Pages), поэтому не выноси ресурсы в отдельные файлы и не подключай CDN. Скрипт разбит на 14 пронумерованных разделов, оглавление — в комментарии в начале `<script>`.

**Экран — 300×200 игровых пикселей, растянутых в 3 раза.** Все координаты и скорости — в этих «кубиках»; `<canvas>` растягивается CSS до 900×600 с `image-rendering: pixelated`. Скан-линии — фон `.screen::after` с `background-size: 100% calc(100% / 200)`, по одной на строку пикселей: поменяешь высоту холста — поменяй и 200.

**Уровни — карты из букв в `LEVELS`.** 13 строк, одна буква — клетка 16×16; верх земли — строка 11, строка 12 видна наполовину. Легенда букв — в комментарии над `LEVELS`. Все строки карты одной длины; на уровне ровно один старт `P` и выход `E` либо дом `D`. На последнем уровне левее дома стоит Соня `G` — встреча с ней и есть финал. Предметы и опасности ставятся в клетку над землёй.

**Правила, без которых уровень становится нечестным** (их нашёл бот, прогнанный через все уровни):
- прыжок с разбега — до 4 клеток вверх и почти 5 вперёд, самый короткий тап — около 2 вверх и 3,5 вперёд;
- вода без опоры — не шире 3 клеток; камни и мостки посреди реки — не уже 3 клеток, иначе прыжок с разбега перелетает камень и не долетает до берега;
- над мухомором и ежом не ставь коробку `B` или низкий карниз из камней: кошка бьётся головой, прыжок обрывается, и она падает прямо на опасность;
- ёж ходит в пределах 2,5 клеток от своего места — не ставь его туда, куда кошка приземляется после бревна или реки.

**Спрайты — рисунки из букв палитры.** Цвета — в `PAL`, рисунки — в разделе 4, `.` — прозрачно. У кошки верх (голова, спина, хвост) общий, кадры бега различаются только лапами: `CAT_TOP` + `CAT_LEGS`. Строки одного рисунка должны быть одной длины, иначе `sprite()` пишет предупреждение в консоль.

**Шрифт свой, 5×7, только заглавные.** Буквы нарисованы решётками в `FONT_SRC`; символ, которого там нет, молча не рисуется. Добавляешь текст с новым знаком — сначала дорисуй глиф.

**Звук появляется только после первого нажатия.** Браузер не даёт играть звук без действия пользователя, поэтому `AudioContext` создаётся в обработчике клавиши или тапа, и заставка до первого нажатия молчит — это не баг. Мелодии записаны нотами в `SONGS`, аккорды и барабаны раскладываются по шестнадцатым в `buildSong()`.

**Телефон — отдельная раскладка на классе `.touch`.** Скрипт ставит его на `<html>`, когда видит сенсорный экран, и CSS по нему показывает кнопки: вертикально — под экраном, горизонтально — по бокам. Крестовина — одна зона (левая половина «влево», правая «вправо»), поэтому палец можно перекатывать, не отрывая.

**Логика идёт ровно 60 шагов в секунду** при любой частоте монитора (накопитель времени в `loop()`), поэтому скорости и таймеры считаются в кадрах этого шага.

**Что проверять после правок:**
- открыть файл двойным кликом и пройти изменённое место — в консоли ни одной ошибки;
- после правки карты — пройти уровень до конца и сверить с правилами выше;
- в DevTools в режиме устройства (телефон вертикально и горизонтально): кнопки видны, страница не прокручивается, можно держать «вправо» и одновременно прыгать;
- звук: M выключает и включает, после паузы (P) музыка продолжается.

## homework-4 — лендинг «Запущу»

Лендинг услуги «запуск AI-сгенерированного кода под ключ» — идея №2 из `homework-3/product-ideas.md`. Аудитория — не-разработчики, которым код написал ChatGPT или Claude; главное действие — заявка на бесплатную оценку. Спека и план — в `homework-4/docs/superpowers/`.

Лендинг — три файла без сборки: `index.html` — только разметка, `styles.css`, `script.js` — отправка формы и подстановка результата демо в поле «Что за проект». Tailwind и CDN здесь сознательно не используются: для трёх файлов обычный CSS проще и нагляднее.

**Стили разбиты на четыре подписанных блока:** `/* ===== 1. Токены и база ===== */`, `2. Первый экран`, `3. Проблема и решение`, `4. FAQ и форма`. Блоки 2–4 стилизуют только свои секции. Все цвета — переменные на `:root`: нужен новый цвет — сначала заведи переменную.

**Форма отправляется на заглушку.** В `action` стоит `https://formspree.io/f/[ВАШ_ID]`, поэтому отправка всегда заканчивается сообщением «Не получилось отправить…», а в консоли появляется сетевая ошибка. Это не баг: нужен настоящий ID из кабинета Formspree. Контакты `@USERNAME` и `you@example.com` — тоже заглушки, страница закрыта `robots=noindex`. `@USERNAME` встречается и в подвале, и в тексте ошибки в `script.js` — меняешь контакт, правь оба места. Когда заменишь все заглушки, убери `robots=noindex` и поправь примечание про заглушки в корневом `index.html`.

**Поле из одних пробелов** встроенная проверка `required` пропускает — его ловит `script.js` и пишет «Заполните все поля.».

**Демо — каждое в своей папке** (`diagnostic/`, `code-check/`, `simulation/`). У демо свои html, css и js; общие цвета, кнопки (в том числе кнопка-ссылка `.link-button`) и карточки берутся из `../styles.css` — не копируй их в стили демо, свои цвета не заводятся. Результат демо уходит в форму лендинга адресом ссылки `../index.html?project=…#form` — `script.js` подставляет текст в поле «Что за проект». Ссылки между страницами ведут на `index.html`, а не на папку: по двойному клику ссылка на папку открывает список файлов. У демо тоже стоит `robots=noindex` — снимай его вместе с лендингом.

**Диагностика `diagnostic/`** — шесть вопросов и паспорт запуска. Вопросы и правила — таблицы `QUESTIONS` и `TOPICS` в `diagnostic.js`, разметку вопросов строит скрипт. По каждой теме срабатывает первое подходящее правило, поэтому порядок правил внутри темы важен. Ответы хранятся в `localStorage` под ключом `zapushchu-diagnostic-answers`. Спека с эталонными паспортами — `docs/superpowers/specs/2026-09-30-diagnostic-demo-design.md`.

**Проверка кода `code-check/`** — вставка кода или выбор файлов и отчёт: тип проекта, что мешает запуску (с номерами строк), что понадобится. Правила — таблицы `PROJECT_TYPES`, `PROBLEM_RULES`, `NEED_RULES` в `code-check.js`; примеры — `examples.js`, они же эталоны. Найденные ключи и пароли маскируются в любой показанной строке (`maskSecrets`), в форму уходят только заголовки находок и номера строк. В `<head>` стоит CSP `connect-src 'none'`: странице запрещены любые сетевые запросы — не убирай его и не добавляй `fetch`. Код и отчёт нигде не сохраняются, даже в браузере. Спека с эталонами и отрицательными случаями — `docs/superpowers/specs/2026-09-30-code-check-demo-design.md`.

**Симуляция `simulation/`** — запуск Telegram-бота из примера проверки кода по шагам. Вкладка «Сам» — 10 шагов с экранами терминала и три развилки, вкладка «Со мной» — три шага клиента; под ними итог: сравнение путей и чеклист, отметки которого уходят в форму. Сценарий — таблицы `STEPS`, `WITH_ME`, `CHECKLIST` в `scenario.js`, логика — `simulation.js`. Числа в сравнении скрипт считает по таблицам — руками их не пиши. Экраны терминала сняты с настоящей Ubuntu 24.04 в Docker или сверены с исходниками программ (раздел 13 спеки): меняешь команду — перепроверь её вывод, иначе знающий человек заметит фальшь. В `localStorage` под ключом `zapushchu-simulation` — вкладка, шаг и отметки чеклиста. Спека — `docs/superpowers/specs/2026-09-30-simulation-demo-design.md`.

**Что проверять после правок:**
- страница открывается двойным кликом, в консоли при загрузке ни одной ошибки;
- на ширине 360 и 1280 px нет горизонтальной прокрутки;
- кнопки «Оценить проект» и «Получить бесплатную оценку» ведут к форме, FAQ раскрывается;
- пустая форма не отправляется, форма из пробелов показывает «Заполните все поля.»;
- диагностика: пропущенный вопрос не даёт показать паспорт; после правки `QUESTIONS` или `TOPICS` — перебор всех сочетаний ответов из плана `docs/superpowers/plans/2026-09-30-diagnostic-demo.md` (задача 1, шаг 7): у каждого паспорта ровно один вывод про сервер и есть «Мониторинг»;
- «Отправить паспорт на бесплатную оценку» открывает лендинг с заполненным полем «Что за проект»;
- проверка кода: три примера дают эталонные отчёты из спеки; после правки правил — все положительные и отрицательные случаи из раздела 12 спеки `docs/superpowers/specs/2026-09-30-code-check-demo-design.md`; в отчёте и в ссылке «Отправить отчёт» нет ключей из примеров;
- симуляция: скрипт проверки сценария из плана `docs/superpowers/plans/2026-09-30-simulation-demo.md` (задача 1, шаг 1) проходит; все 10 шагов проходятся, «Дальше» на развилке закрыта до верного ответа; «Отправить чеклист на бесплатную оценку» открывает лендинг с заполненным полем «Что за проект»; при печати виден только чеклист.
