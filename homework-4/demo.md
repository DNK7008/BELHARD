# Демо «Запущу»: три варианта рабочей части продукта

> Идея — №2 из [homework-3/product-ideas.md](../homework-3/product-ideas.md): запуск
> AI-сгенерированного кода под ключ. Лендинг — [index.html](index.html), его спека —
> [docs/superpowers/specs/2026-09-28-zapushchu-landing-design.md](docs/superpowers/specs/2026-09-28-zapushchu-landing-design.md).
> Аудитория — не-разработчики, которым код написал ChatGPT или Claude. Главное действие —
> заявка на бесплатную оценку.
>
> Ограничения: только статика на GitHub Pages — без сервера, API-ключей, библиотек и шрифтов
> из интернета и без сборки. Работает офлайн и с телефона.

## Общее для всех вариантов

- **Демо ведёт к заявке, а не уводит от неё.** Каждый вариант заканчивается кнопкой, которая
  переносит результат в поле «Что за проект» формы на лендинге. Результат передаётся через
  адрес ссылки, сервер для этого не нужен. Без такой кнопки человек поиграет с демо и
  уйдёт, так и не дойдя до формы.
- **Расчёт стоимости сознательно не беру.** Спека лендинга запрещает цены и выдуманные цифры,
  а калькулятор без цен превращается в угадайку.

---

## Вариант 1. «Что нужно вашему проекту» — диагностика по ответам

1. **Что человек делает на экране.** Отвечает на шесть вопросов о своём проекте обычными
   словами, без слов «сервер» и «база данных», и сразу видит, что понадобится для запуска.

   Вопросы (черновик):
   - Что сделал AI? — сайт-визитку / Telegram-бота / сайт с формой или личным кабинетом /
     программу для себя или команды / не знаю
   - Программа должна запоминать что-то между визитами — заказы, записи, пользователей? —
     да / нет / не знаю
   - Кто будет ею пользоваться? — только я / моя команда / любой человек из интернета
   - Она обращается к платным сервисам — ChatGPT, приёму оплаты, рассылкам? — да / нет / не знаю
   - Она должна работать сама, без человека: присылать напоминания, что-то делать ночью? —
     да / нет / не знаю
   - Где сейчас код? — в чате с AI / в архиве / на GitHub

2. **Что получает в конце.** Карточку «Паспорт запуска»:
   - **что нужно проекту** — те же термины, что на лендинге (сервер, домен, SSL, мониторинг),
     и по ответам ещё: база данных с резервными копиями, безопасное хранение ключей от платных
     сервисов, вход по паролю;
   - **что НЕ нужно** — например: «Для сайта-визитки сервер не нужен, его можно разместить
     бесплатно». Честный ответ «вам это не нужно» вызывает больше доверия, чем любая
     реклама;
   - **на что обратить внимание** — под каждым пунктом строка «почему: вы ответили …»;
   - на ответы «не знаю» — пункт «выясню при бесплатной оценке»;
   - кнопку «Отправить паспорт на оценку», которая переносит его в форму заявки.

   Паспорт сохраняется в браузере: человек возвращается на страницу и видит его снова.

3. **Что заменяет сервер.** Набор правил — таблица «ответ → что нужно проекту» прямо в
   JavaScript, и `localStorage` для сохранения паспорта. Это та же логика, по которой
   администратор в первые пять минут разговора прикидывает объём работы: программа помнит
   данные — нужны база и резервные копии; обращается к ChatGPT — нужен ключ, и хранить его в
   коде нельзя; работает ночью сама — нужен сервер, бесплатный хостинг статики не подойдёт.
   Это честно: демо не выдаёт себя за «умный анализ», каждый вывод показывает, из какого
   ответа он получен. Ответы никуда не уходят и хранятся только в браузере человека.

4. **Трудозатраты:** вечер. Одна страница, шесть вопросов и таблица правил на 15–20 строк.

5. **Кнопка на лендинге:** «Узнать за минуту, что нужно для запуска моего проекта»

## Вариант 2. «Проверка кода прямо в браузере» — песочница с заготовленными примерами

1. **Что человек делает на экране.** Вставляет код, который написал AI, или открывает один из
   трёх готовых примеров (Telegram-бот на Python, сайт с формой на Flask, страница-калькулятор
   на HTML), нажимает «Проверить» и видит разбор по строкам.

2. **Что получает в конце.** Отчёт из трёх блоков:
   - **Что это за проект** — например: «Telegram-бот на Python, библиотека aiogram» или
     «Обычный сайт из HTML — сервер ему не нужен»;
   - **Что мешает запуску** — каждая находка с номером строки и объяснением простыми словами
     (правила — в таблице ниже). Найденные ключи показываются замаскированными: `sk-…a1b2`;
   - **Что понадобится** — сервер или бесплатный хостинг, где хранить ключи, нужны ли
     резервные копии.

   Под отчётом кнопка «Отправить отчёт на оценку». В форму уходит только список находок,
   **без самих ключей и без кода**.

   Примеры правил:

   | Что ищем | Как выглядит в коде | Что говорим человеку |
   |---|---|---|
   | Токен Telegram-бота | `123456789:AAH…` | Ключ от бота лежит прямо в коде: кто увидит код, тот управляет ботом. |
   | Ключ OpenAI | `sk-…` | Ключ от платного сервиса в коде: по нему с вашего счёта могут тратить деньги. |
   | Режим отладки | `debug=True` | При ошибке сайт покажет посетителю свои внутренности. |
   | Локальный адрес | `localhost`, `127.0.0.1` | Этот адрес работает только на вашем компьютере, из интернета он не откроется. |
   | Данные в файле | `sqlite3`, `open("data.json", "w")` | Данным нужны резервные копии, иначе одна поломка — и все записи пропали. |
   | Работа без остановки | `while True`, `schedule`, `polling` | Программе нужен сервер, который не выключается. |
   | Нет серверного кода | только HTML, CSS, JS | Сервер не нужен: такой сайт размещается бесплатно. |

3. **Что заменяет сервер.** Набор правил-шаблонов (12–15 регулярных выражений) и три
   заготовленных примера кода, в которых эти проблемы есть. Найти в тексте `import aiogram`,
   строку вида `123456789:AA…` или `debug=True` — задача для поиска по шаблону: ни сервер, ни
   нейросеть для этого не нужны. Именно с этого администратор и начинает смотреть чужой код.
   Честно это потому, что:
   - под отчётом открыт полный список правил — видно, что именно проверялось;
   - на странице прямо написано: «Это первая автоматическая проверка, а не аудит. „Ничего не
     найдено“ не значит „безопасно“»;
   - код никуда не отправляется и не сохраняется даже в браузере. Человек может проверить
     это сам: отключить интернет, и проверка продолжит работать. Для того, кто боится вставлять свой код на чужой сайт, это главный аргумент.

   Честное ограничение: код можно вставить текстом или выбрать отдельными файлами
   (`<input type="file">` работает и на телефоне). Архив `.zip` без библиотеки не прочитать,
   и страница об этом прямо говорит.

4. **Трудозатраты:** выходные. Основное время уйдёт на правила с понятными объяснениями и на
   три реалистичных примера кода.

5. **Кнопка на лендинге:** «Проверить мой код — он не покинет ваш браузер»

## Вариант 3. «Сам или со мной» — симуляция запуска по шагам

1. **Что человек делает на экране.** Проходит по шагам запуск готового Telegram-бота и
   переключается между двумя режимами. «Сам» — экраны терминала, панели хостинга и настоящие
   сообщения об ошибках. «Со мной» — те же этапы глазами клиента «Запущу».

   Путь «Сам» (черновик): арендовать сервер → подключиться по SSH → установить Python и
   библиотеки → перенести код → убрать токен из кода в файл `.env` → запустить → настроить
   автозапуск → привязать домен (DNS) → получить SSL-сертификат → настроить мониторинг.

   На трёх шагах развилка: что-то пошло не так (`ModuleNotFoundError`, бот молчит после
   закрытия терминала, токен попал в публичный репозиторий). Человек выбирает, что делать, и
   видит последствия выбора.

   Путь «Со мной»: прислать код → получить оценку → получить ссылку и доступы.

2. **Что получает в конце.** Итоговый экран с двумя вещами:
   - сравнение путей: сколько шагов и новых терминов было в режиме «Сам» и сколько в режиме
     «Со мной». Числа считаются по самой симуляции, в черновике выше — 10 шагов против 3,
     ничего не выдумано;
   - чеклист «Что должно быть у запущенного проекта» из 10 пунктов, который можно скопировать
     или распечатать. Он пригодится, даже если человек решит запускать сам, и заодно честно
     показывает объём работы.

3. **Что заменяет сервер.** Заготовленный сценарий — массив шагов с текстом экранов,
   ошибками и вариантами выбора. Терминал на странице ненастоящий, и над ним прямо написано:
   «Это запись настоящего запуска, а не живой сервер». Это честно: демо ничего не запускает и
   не делает вид, что запускает, — это интерактивная инструкция, как видео, только с
   развилками. Пройденные шаги можно запоминать в `localStorage`.

4. **Трудозатраты:** выходные — на один сценарий (Telegram-бот). Большая часть времени уйдёт
   на тексты: команды и ошибки нужно сверить с настоящим сервером, иначе знающий человек
   заметит фальшь. Три сценария (бот, сайт, внутренний инструмент) — уже амбициозно.

5. **Кнопка на лендинге:** «Попробовать запустить бота самому — без риска что-то сломать»

## Сравнение

| | 1. Диагностика | 2. Проверка кода | 3. Симуляция |
|---|---|---|---|
| С чем работает | с представлением человека о проекте | с настоящим кодом человека | с чужим примером |
| С телефона | удобнее всех: только нажатия | неудобно вставлять код, спасают примеры | удобно: только нажатия |
| Трудозатраты | вечер | выходные | выходные |
| Слабое место | человек не знает, что внутри его кода, и может ответить неточно | «ничего не найдено» легко принять за «всё безопасно» — нужна явная оговорка | показывает сложность, а не решение; легко скатиться в запугивание |

## Рекомендация: вариант 2 — проверка кода в браузере

Суть «Запущу»: вы присылаете код, я смотрю его и говорю, что нужно для запуска. Вариант 2 —
это второй шаг из блока «Как это работает» («Я оцениваю — бесплатно»), только в миниатюре и
мгновенно. Почему именно он:

1. **Он работает с настоящим кодом посетителя**, а не с его представлением о коде (слабость
   варианта 1) и не с чужим примером (слабость варианта 3). Человек пробует не демо про
   продукт, а кусочек самого продукта.
2. **Он показывает экспертизу делом.** Строка «в строке 12 лежит ключ от вашего бота» убеждает
   сильнее любого текста на лендинге. И это прямой ответ на третью карточку проблемы:
   «Страшно, что всё сломается или взломают».
3. **Ограничение превращается в преимущество.** «Код не покидает ваш браузер» — это не
   вынужденная мера из-за GitHub Pages, а обещание, которое человек может проверить сам,
   отключив интернет.

Оговорки, чтобы выбор был честным:

- Нужны выходные, а не вечер. Если есть только вечер, делай вариант 1: по сути он слабее, зато
  быстрее всех и удобнее с телефона.
- Готовые примеры в варианте 2 обязательны. Без них с телефона демо почти не попробовать, а
  тот, кто зашёл просто посмотреть, уйдёт, так и не увидев отчёт.
