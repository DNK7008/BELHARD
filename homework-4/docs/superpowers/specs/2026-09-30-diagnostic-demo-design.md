# Демо «Что нужно вашему проекту» — спецификация

> Дата: 2026-09-30. Путь brainstorming: Architectural (новая страница и общая часть для трёх демо).
> Источник: [demo.md](../../../demo.md), вариант 1. Варианты 2 и 3 — отдельные спеки после этой.
> Лендинг, к которому относится демо: [2026-09-28-zapushchu-landing-design.md](2026-09-28-zapushchu-landing-design.md).

## 1. Зачем

Маленькая рабочая часть продукта «Запущу», которую можно потрогать в браузере. Человек
отвечает на шесть вопросов о своём проекте простыми словами и получает «паспорт запуска»:
что понадобится, что не понадобится и что я проверю при бесплатной оценке. Паспорт одной
ссылкой переносится в форму заявки на лендинге.

Попутно появляется общая часть, которую возьмут демо 2 и 3: своя папка у каждого демо,
общие стили из `../styles.css` и передача результата в форму через адрес ссылки.

**Аудитория и тон** — как у лендинга: не-разработчики, спокойно, на «вы», без жаргона.

### Критерии успеха

1. Шесть вопросов проходятся с телефона примерно за минуту; каждый вариант ответа — область
   для нажатия высотой не меньше 44 px.
2. У каждого пункта паспорта есть строка «Почему», которая объясняет, откуда взялся вывод.
3. «Отправить паспорт на бесплатную оценку» открывает лендинг на форме с заполненным полем
   «Что за проект».
4. После перезагрузки страницы ответы и паспорт на месте.
5. Работает двойным кликом (`file://`) и на GitHub Pages.
6. При загрузке и во время работы в консоли нет ошибок; на ширине от 360 до 1440 px нет
   горизонтальной прокрутки.
7. Перебор всех 1215 сочетаний ответов проходит проверки из раздела 8.

## 2. Ограничения и вне рамок

**Ограничения:** только статика — без сервера, API-ключей, библиотек, шрифтов и CDN, без
сборки. Работает офлайн и с телефона. Соглашения лендинга: цвета — только через переменные
`--color-*` из `styles.css`, никаких атрибутов `style` и `<script>` без `src`, комментарии
на русском и объясняют «зачем», отступ 2 пробела, в JS двойные кавычки и точка с запятой.

**Вне рамок:**
- демо 2 и 3;
- печать, копирование и скачивание паспорта;
- аналитика и отправка ответов куда-либо, кроме формы заявки по нажатию человека;
- тёмная тема;
- правки текстов лендинга, кроме одной строки из раздела 6.

## 3. Файлы

```
homework-4/
├─ index.html          + строка со ссылкой на демо в секции формы (раздел 6)
├─ script.js           + подстановка ?project= в поле «Что за проект» (раздел 6)
├─ styles.css          без изменений
└─ diagnostic/
   ├─ index.html       каркас страницы
   ├─ diagnostic.css   стили вопросов и паспорта
   └─ diagnostic.js    вопросы, правила и поведение страницы
```

Плюс в корне репозитория: ссылка в оглавлении `index.html` и абзац про демо в `CLAUDE.md`.

### Обязанности файлов

**`diagnostic/index.html`** — только каркас: шапка, вводный блок, пустой контейнер под
вопросы, скрытый блок паспорта, подвал. Тексты вопросов и правил в разметке не живут.

**`diagnostic/diagnostic.css`** — подключается **после** `../styles.css` и пользуется его
классами: `.container`, `.btn`, `.site-header`, `.logo`, `.section`, `.section-title`,
`.section-intro`, `.cards`, `.card`, `.site-footer`. Свои стили — в двух подписанных блоках:

```
/* ===== 1. Вопросы ===== */
/* ===== 2. Паспорт ===== */
```

Новых цветов нет. Если понадобится — сначала переменная на `:root` в `styles.css`.

**`diagnostic/diagnostic.js`** — подключается `<script src="diagnostic.js" defer>`. Пять
подписанных разделов:

```
// ===== 1. Вопросы =====              таблица QUESTIONS
// ===== 2. Правила =====              таблицы GROUPS и TOPICS
// ===== 3. Подсчёт паспорта =====     matchRule, buildPassport, passportToText
// ===== 4. Сохранение ответов =====   loadAnswers, saveAnswers, clearAnswers
// ===== 5. Страница =====             отрисовка и обработчики
```

Функции разделов 3 и 4 не трогают разметку — их можно вызвать из консоли браузера и
проверить отдельно. `answers` везде — объект вида `{ kind: "bot", data: "yes", … }`.

- `matchRule(rule, answers)` → массив `id` вопросов-причин (пустой у правила без условий)
  или `null`, если правило не сработало;
- `buildPassport(answers)` → массив пунктов `{ group, title, text, why }` в порядке тем,
  где `why` — готовая строка «Почему: …»;
- `passportToText(answers)` → текст для формы заявки (раздел 5).

## 4. Вопросы

Порядок на странице — как в таблице. `id` вопроса — это `name` у радиокнопок, `id` ответа —
их `value`. Подпись нужна для строки «Почему» и для текста в форме заявки.

| `id` | Вопрос | Подпись | Ответы (`id` — текст) |
|---|---|---|---|
| `kind` | Что сделал для вас AI? | Что сделал AI | `landing` — Сайт-визитку; `bot` — Telegram-бота; `webapp` — Сайт с формой, личным кабинетом или оплатой; `tool` — Программу для работы — таблицу, калькулятор, отчёт; `unknown` — Не знаю, как это назвать |
| `data` | Программа должна запоминать что-то между визитами — заказы, записи, пользователей? | Запоминает данные | `yes` — Да; `no` — Нет; `unknown` — Не знаю |
| `audience` | Кто будет ею пользоваться? | Кто пользуется | `me` — Только я; `team` — Моя команда; `any` — Любой человек из интернета |
| `paid` | Она обращается к платным сервисам — ChatGPT, приёму оплаты, рассылкам? | Платные сервисы | `yes` — Да; `no` — Нет; `unknown` — Не знаю |
| `auto` | Она должна работать сама, без человека — присылать напоминания, что-то делать ночью? | Работает сама | `yes` — Да; `no` — Нет; `unknown` — Не знаю |
| `where` | Где сейчас код? | Где код | `chat` — В чате с AI; `archive` — В архиве или папке на компьютере; `github` — На GitHub |

Сочетаний ответов: 5 × 3 × 3 × 3 × 3 × 3 = 1215.

## 5. Правила

### Группы паспорта

| `id` | Заголовок |
|---|---|
| `need` | Понадобится |
| `notNeeded` | Не понадобится |
| `check` | Проверю при бесплатной оценке |

Группы идут в этом порядке. Пустая группа не показывается. Пункты внутри группы — в порядке тем.

### Как срабатывает правило

Правило может иметь условие `all`, условие `any`, оба или ни одного. Условие — объект
`{ idВопроса: [idОтветов] }`.

- `all` выполнено, если **каждый** указанный вопрос получил один из перечисленных ответов.
- `any` выполнено, если **хотя бы один** указанный вопрос получил один из перечисленных ответов.
- Правило срабатывает, если выполнены все его условия. Правило без условий срабатывает всегда.
- **Причины** сработавшего правила — вопросы из его условий, ответы на которые совпали.
  Для `any` это только совпавшие вопросы, а не все перечисленные.

### Темы

Правила сгруппированы в 8 тем. **По каждой теме берётся первое сработавшее правило**;
если не сработало ни одно — тема в паспорт не попадает. Тексты окончательные.

**1. Где работает**

| | Условие | Группа | Заголовок | Текст |
|---|---|---|---|---|
| а | all: `kind`=`tool`, `audience`=`me` | check | Сервер или ваш компьютер | Программу только для себя иногда проще запускать на своём компьютере. Посмотрю код и скажу, что выйдет проще и дешевле. |
| б | any: `kind`∈{`bot`,`webapp`,`tool`}, `data`=`yes`, `paid`=`yes`, `auto`=`yes` | need | Сервер | Компьютер в дата-центре, который не выключается: программа работает круглосуточно, даже когда ваш ноутбук закрыт. |
| в | all: `kind`=`landing`, `data`=`no`, `paid`=`no`, `auto`=`no` | notNeeded | Сервер | Сайт из готовых страниц можно разместить на бесплатном хостинге — платить за сервер не придётся. |
| г | any: `kind`=`unknown`, `data`=`unknown`, `paid`=`unknown`, `auto`=`unknown` | check | Нужен ли сервер | Зависит от того, что делает код. Посмотрю — возможно, хватит бесплатного хостинга. |

Правило «г» ловит всё, что не поймали «а»–«в»: после них остаётся `kind` из {`landing`,
`unknown`} без единого «да», и это либо `kind`=`unknown`, либо хотя бы одно «Не знаю».
Поэтому тема 1 даёт вывод **всегда** — это проверяется перебором.

**2. Адрес**

| | Условие | Группа | Заголовок | Текст |
|---|---|---|---|---|
| а | all: `kind`=`bot` | notNeeded | Домен | Бота находят в Telegram по имени — отдельный адрес сайта ему не нужен. |
| б | any: `kind`∈{`landing`,`webapp`}, `audience`∈{`team`,`any`} | need | Домен и SSL-сертификат | Адрес вида вашпроект.by и замочек в адресной строке: данные посетителей шифруются. |

**3. Данные**

| | Условие | Группа | Заголовок | Текст |
|---|---|---|---|---|
| а | all: `data`=`yes` | need | База данных и резервные копии | Заказы и записи хранятся в базе, а её копия каждый день уезжает в другое место: одна поломка не сотрёт всё. |
| б | all: `data`=`unknown` | check | Хранит ли программа данные | Если хранит, понадобятся база и резервные копии. Это видно по коду. |

**4. Ключи**

| | Условие | Группа | Заголовок | Текст |
|---|---|---|---|---|
| а | all: `paid`=`yes` | need | Надёжное место для ключей | Ключ от ChatGPT или приёма оплаты — это доступ к вашим деньгам. На сервере он хранится отдельно от кода, а не внутри него. |
| б | all: `paid`=`unknown` | check | Нет ли в коде ключей | AI часто вписывает ключи прямо в код. Если найду — перенесу в надёжное место. |

**5. Работа без человека**

| | Условие | Группа | Заголовок | Текст |
|---|---|---|---|---|
| а | all: `auto`=`yes` | need | Автозапуск и расписание | После сбоя программа поднимется сама, а напоминания и ночные задачи будут выполняться по расписанию. |
| б | all: `auto`=`unknown` | check | Работает ли программа по расписанию | Напоминания и ночные задачи требуют отдельной настройки — увижу это по коду. |

**6. Доступ**

| | Условие | Группа | Заголовок | Текст |
|---|---|---|---|---|
| а | all: `audience`∈{`me`,`team`} | need | Вход только для своих | Закрою программу паролем или списком разрешённых людей — посторонние не смогут ею пользоваться, даже если найдут. |
| б | all: `audience`=`any`, `kind`=`webapp` | need | Защита от спама | Открытую всем форму быстро находят спам-боты. Поставлю защиту, чтобы заявки приходили от людей. |

**7. Присмотр**

| | Условие | Группа | Заголовок | Текст |
|---|---|---|---|---|
| а | без условий, причина — «входит в любой запуск» | need | Мониторинг | Если проект перестанет открываться, я узнаю об этом первым. |

**8. Где код**

| | Условие | Группа | Заголовок | Текст |
|---|---|---|---|---|
| а | all: `where`=`chat` | check | Код из чата | В чате код обычно разбит на куски. Соберу их в один проект и проверю, что ничего не потерялось. |
| б | all: `where`=`github` | check | Открыт ли репозиторий | Открытый репозиторий видят все. Проверю, не попали ли туда пароли и ключи. |

Всего 17 правил.

### Строка «Почему»

Формат: `Почему: ` + причины через `; `, каждая — `Подпись — «Текст ответа»`. Тексты ответов
не переделываются (заглавная буква остаётся — её оправдывают кавычки). У правила без
условий вместо причин — его фиксированный текст.

- `Почему: Что сделал AI — «Telegram-бота»; Запоминает данные — «Да»; Работает сама — «Да»`
- `Почему: входит в любой запуск`

### Эталонные примеры

**Пример А** — `kind`=`bot`, `data`=`yes`, `audience`=`any`, `paid`=`no`, `auto`=`yes`, `where`=`chat`:
- Понадобится: Сервер *(Почему: Что сделал AI — «Telegram-бота»; Запоминает данные — «Да»;
  Работает сама — «Да»)*, База данных и резервные копии, Автозапуск и расписание, Мониторинг.
- Не понадобится: Домен.
- Проверю при бесплатной оценке: Код из чата.

**Пример Б** — `kind`=`landing`, `data`=`no`, `audience`=`any`, `paid`=`no`, `auto`=`no`, `where`=`archive`:
- Понадобится: Домен и SSL-сертификат *(Почему: Что сделал AI — «Сайт-визитку»; Кто
  пользуется — «Любой человек из интернета»)*, Мониторинг.
- Не понадобится: Сервер.
- Группы «Проверю при бесплатной оценке» нет.

### Текст для формы заявки

`passportToText` собирает обычный текст (без HTML), строки через `\n`:

```
Паспорт запуска из диагностики на сайте
Что сделал AI: Telegram-бота
Запоминает данные: Да
Кто пользуется: Любой человек из интернета
Платные сервисы: Нет
Работает сама: Да
Где код: В чате с AI

Понадобится: Сервер; База данных и резервные копии; Автозапуск и расписание; Мониторинг
Не понадобится: Домен
Проверю при бесплатной оценке: Код из чата
```

Первые семь строк — всегда (заголовок и шесть ответов в порядке вопросов), затем пустая
строка, затем по строке на каждую непустую группу: заголовок группы, двоеточие, заголовки
пунктов через `; `. Пояснения и строки «Почему» в текст не входят. Длина — не больше 2000
символов (`maxlength` поля «Что за проект»).

## 6. Страница и поведение

### `diagnostic/index.html`

- `<html lang="ru">`, `<meta charset="utf-8">`, viewport `width=device-width, initial-scale=1`.
- `<title>`: `Что нужно вашему проекту — Запущу`
- `<meta name="description">`: `Ответьте на шесть вопросов о проекте, который написал AI, и узнайте, что понадобится для его запуска.`
- `<meta name="robots" content="noindex">` и `<link rel="icon" href="data:,">` — как на лендинге.
- Стили: `../styles.css`, затем `diagnostic.css`. Скрипт: `diagnostic.js` с `defer`.

**Шапка** `header.site-header` — как на лендинге: «Запущу» → `../index.html`, кнопка-ссылка
«Оценить проект» → `../index.html#form`.

**Вводный блок** `section.section`:
- `h1.section-title`: **Что нужно вашему проекту**
- `p.section-intro`: «Шесть вопросов простыми словами — и вы увидите, что понадобится для
  запуска, а что нет. Ответы остаются в вашем браузере и никуда не отправляются.»
- `<noscript>`: «Для диагностики нужен JavaScript. Если он выключен, просто
  [оставьте заявку](../index.html#form) — я разберусь сам.»
- `<form id="quiz" class="quiz">` — внутри пустой `<div id="questions">` и кнопка
  `<button class="btn" type="submit">Показать паспорт</button>`. Атрибута `novalidate` нет:
  пропущенный вопрос ловит сам браузер.

**Паспорт** `<section id="passport" class="section section--soft" hidden>`:
- `<h2 id="passport-title" class="section-title" tabindex="-1">Паспорт запуска</h2>` —
  `tabindex="-1"`, чтобы на заголовок можно было перенести фокус из скрипта.
- `<div id="passport-groups">` — сюда скрипт рисует группы.
- `p.passport__note`: «Это первая прикидка по правилам. Точный ответ дам, когда посмотрю код.»
- Действия: ссылка-кнопка `<a id="send-passport" class="btn" href="../index.html#form">Отправить
  паспорт на бесплатную оценку</a>` и `<button id="restart" class="link-button" type="button">Пройти заново</button>`.

**Подвал** `footer.site-footer` — без контактов, чтобы заглушки не расползались по файлам:
«Запущу — запуск AI-проектов под ключ» и ссылка «← На главную» → `../index.html`.

### Разметка, которую строит скрипт

Вопрос:

```html
<fieldset class="question">
  <legend>1. Что сделал для вас AI?</legend>
  <div class="answers">
    <label class="answer"><input type="radio" name="kind" value="landing" required> Сайт-визитку</label>
    …
  </div>
</fieldset>
```

Группа паспорта:

```html
<div class="passport__group">
  <h3>Понадобится</h3>
  <ul class="cards">
    <li class="card">
      <h4>Сервер</h4>
      <p>Компьютер в дата-центре…</p>
      <p class="why">Почему: Что сделал AI — «Telegram-бота»; …</p>
    </li>
  </ul>
</div>
```

Все тексты вставляются через `textContent`, не через `innerHTML`.

### Поведение

1. **Загрузка.** Скрипт рисует вопросы из `QUESTIONS`, восстанавливает ответы из
   `localStorage` и отмечает радиокнопки. Если отвечены все шесть вопросов — сразу рисует и
   показывает паспорт (без переноса фокуса).
2. **Изменение ответа** (`change` на форме). Ответы сохраняются. Если паспорт уже показан — он
   перерисовывается, чтобы не расходиться с ответами.
3. **«Показать паспорт»** (`submit`). Событие приходит, только если браузер убедился, что все
   группы отвечены. `preventDefault()`, паспорт рисуется, `hidden` снимается, фокус переносится
   на `#passport-title` — на телефоне страница прокручивается к результату.
4. **Отрисовка паспорта** каждый раз заново собирает `#passport-groups` и обновляет `href`
   у `#send-passport`: `../index.html?project=` + `encodeURIComponent(passportToText(…))` + `#form`.
5. **«Пройти заново».** Очищает сохранённые ответы, сбрасывает форму (`form.reset()`),
   прячет паспорт, переносит фокус на первую радиокнопку.

### Сохранение

- Ключ `localStorage`: `zapushchu-diagnostic-answers`, значение — JSON вида
  `{"kind":"bot","data":"yes",…}`.
- При чтении берутся только известные вопросы и известные ответы — старые или испорченные
  данные молча отбрасываются.
- Каждое обращение к `localStorage` обёрнуто в `try/catch`: в приватном режиме или при запрете

**`homework-4/script.js`** — после объявления констант:

```js
// Демо-страницы (например, diagnostic/) передают результат в адресе: index.html?project=…#form.
// Подставляем его в поле «Что за проект», чтобы человеку не пришлось писать заново.
const projectFromDemo = new URLSearchParams(window.location.search).get("project");
if (projectFromDemo) {

  projectField.value = projectFromDemo.slice(0, projectField.maxLength);
}
```

Текст пишется в `value`, а не в разметку, поэтому чужая ссылка с `?project=` ничего не
внедрит в страницу — только заполнит поле, которое человек видит до отправки.
